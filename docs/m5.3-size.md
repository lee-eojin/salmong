# M5.3: download-size method

**Status: method defined. Budget NOT SET. M5.3 is NOT complete.** This file says how salmong measures download size. No number here passes or fails anything. The rest of M5.3 (LTO, `opt-level`, `wasm-opt`) has not started. The cost of `serde_json` has one record below and no target to judge it against.

## What counts

Download size is the sum of the response body bytes of every file in `dist/`, as a browser fetches them on a cold load with an empty cache.

| File | Role |
|---|---|
| `index.html` | The page |
| `salmong-game-<hash>.js` | wasm-bindgen glue |
| `salmong-game-<hash>_bg.wasm` | The game |

Any other file that later lands in `dist/` counts too, so a new asset cannot stay out of the total.

These do not count:

- `dist/.trunk-lock`, the empty lock file Trunk leaves in `dist/`. No browser fetches it.
- `/favicon.ico`. Chrome asks for it and gets a 404, because `dist/` has no such file.
- HTTP headers and TLS, which depend on the host.
- Later visits, which depend on the browser cache.

Chrome 156 confirmed this list on the box. On a cold load it fetched each of the three files once, plus the `/favicon.ico` 404, so the `preload` link does not fetch the wasm twice. With the files served as gzip and as brotli, the response body bytes equalled the `gzip` and `brotli` columns exactly, and the app still reached `backend: BrowserWebGpu`.

The script reads `index.html` only. It cannot see a URL that the wasm builds at run time, so repeat the Chrome check when the game first loads an asset at run time.

## How to measure

```sh
scripts/measure-size.sh
```

The script runs `trunk build --release --offline`, then `node scripts/measure-size.mjs dist`. A run takes 2 to 3 minutes on the box with a warm build, nearly all of it brotli. Build logs go to stderr. Stdout is the table, then one line of JSON as the last line:

```sh
scripts/measure-size.sh 2>/dev/null | tail -n 1 | jq .total
```

`measure-size.mjs` prints nothing on stdout and exits 1 if any of these is true:

- `dist/` is missing, or has no `index.html`.
- `index.html` loads no wasm, loads a file that is not in `dist/`, or loads anything from another origin.
- `dist/` holds two builds of one file, such as two wasm files.
- `dist/` holds a hidden file other than `.trunk-lock`. A failed Trunk build leaves `dist/.stage/`, which would count every file twice.
- `dist/` holds something that is not a regular file.

## Columns

| Column | Meaning |
|---|---|
| `raw` | Bytes on disk |
| `gzip` | GNU `gzip -9 -n`. `-n` leaves out the file name and time, so the size does not depend on Trunk's hash |
| `brotli` | Node's `zlib` at quality 11, window 24 |

The tool is part of the method. At level 9, the same wasm is 10,429,417 bytes with GNU gzip, 10,401,703 with Python's zlib and 10,586,636 with Node's zlib. Brotli at window 22, Node's default, gives 5,603,218 bytes instead of 5,455,864.

Both columns are what a host sends when it serves files compressed ahead of time. A host that compresses while it serves may use a lower level, and then sends more: brotli at quality 5, window 22 gives 6,933,958 bytes for the same wasm.

## JSON record

| Field | Meaning |
|---|---|
| `schema` | Record format, 1 |
| `commit`, `dirty` | `HEAD`, and whether the working tree had changes |
| `wasm_opt` | `data-wasm-opt` from `web/index.html`, or `default` if it is unset |
| `tools` | `rustc`, `trunk`, `wasm_bindgen`, `gzip`, `node` and `brotli` versions |
| `method` | gzip command and brotli settings |
| `files` | One entry per file: `name` without Trunk's hash, `sha256`, `raw`, `gzip`, `brotli` |
| `total` | Sum of each column |

The record holds no time stamp, so two runs of one tree print the same bytes.

## Comparing records

- Compare totals only when `tools` and `method` are equal.
- Take records on the box, the M5.3 machine in the plan. The wasm stores the Cargo registry path 1,059 times in panic and log locations, so a different `CARGO_HOME` changes the bytes. A path 10 characters longer added 10,634 raw bytes and 1,085 gzip bytes. The checkout path has no effect: two cold builds at different paths gave the same `sha256`.
- Do not record a run with `dirty` set to `true` here.
