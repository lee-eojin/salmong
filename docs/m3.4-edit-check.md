# M3.4: Edit continuity check

**Status: box checks PASS; laptop check PENDING.**

M3.4 checks that network edits made while buses carry riders cause no bus jump and lose no rider, in what is drawn, not only in the sim. M3.4a proved the sim side headless (`tests/bus_interp.rs`). This unit adds the drawn side, an edit issued while paused (Q10), and a browser run on the reference laptop.

## The `?replay=edits` body

Scenario 0, `salmong_game::edits::body()`:

| Tick | Command | Kind |
|---|---|---|
| 0 | `AddRoute [1,0,2]` | route 0 |
| 240 | `EditRoute 0 -> [2,0,1]` | reverse |
| 390 | `EditRoute 0 -> [1,0]` | shrink, issued while paused |
| 732 | `EditRoute 0 -> [2,3]` | disjoint |
| 737 | `AddRoute [1,0]` | route 1 |
| 745 | `RemoveRoute 0` | remove |

A route 0 bus carries a rider at every route 0 edit, and moves with it at three of them. Scenario 0 spawns slowly, so the late edits sit close together where riders are on board.

At tick 390 the replay pauses the clock. On hold frame 60 it pushes the shrink into the pending commands, and on hold frame 240 it resumes. Q10 says the edit binds to the first tick after resume, so the command log stamps it at tick 390 and the hashes equal a plain replay of the full body.

## Line formats

```text
salmong: replay tick=<t> hash=<16 hex> frame=<n>
salmong: replay edits tick=<t> riders=<r> queued=<q> delivered=<d> spawned=<s> rejected=<n> step=<milli> draw=<milli> draw_over=<n> lost=<n>
salmong: replay paused tick=<t> rev=<table_rev> pending=<n> frame=<n>
salmong: replay bound tick=<t> rev=<table_rev> pending=<n> frame=<n>
salmong: replay done tick=900
```

`step` is the largest per-tick bus move so far, in thousandths of a grid unit. `draw` is the largest drawn move between two frames. `draw_over` counts frames where a drawn move exceeded the travel of the ticks it spans. `lost` counts frames where drawn riders, drawn queue, badges and delivered did not add up to spawned.

## Laptop procedure

Use the reference laptop and the command-line route of [m0.3-webgpu-check.md](m0.3-webgpu-check.md) and [m3.1-render-check.md](m3.1-render-check.md).

1. On the box, write `expect-edits.txt` with `cargo run --locked -q -p salmong-game --example edits_expect`.
2. On the laptop, build the unit commit with `trunk build --release --offline` and serve `dist/` on port 8080.
3. Open `http://localhost:8080/?replay=edits` in a separate Chrome profile at busy-wait 0, about 40 and about 110 ms per frame. Keep the window visible and the mouse off the canvas: a live pointer can add commands.
4. Record the measured canvas size and device-pixel ratio. No check depends on the size.
5. Compare hash, stats, paused and bound lines with `expect-edits.txt`, and keep a screenshot during the hold and one after the done line.
6. Re-run `?replay=demo` with the M3.1 driver, and open the page without a switch.
