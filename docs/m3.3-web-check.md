# M3.3: Web game check

**Status: PENDING (box and laptop).**

M3.3 makes the plain page a playable game: scenario 0 with its pack seed, ticks from the first left press, Space and 1 and 2 for pause and speed, a pause sign and an x2 sign, a game-over panel with the run score and the device best, and restart by a press. The check comes from plan section 8: a scripted game ends at the same tick, score and `state_hash` as headless, and the browser build re-checks Q9 to Q11.

## Pages

| URL | What it does |
|---|---|
| `/` | The game. `Menu` (board drawn, no tick) until the first left press, then `Playing`, then `GameOver`. A left press 1 s or more after game over restarts into `Menu` |
| `/?replay=over` | The scripted game: `salmong_game::game::body()` fed by `ReplayFeed`, no `Menu` wait. Pointer and keys are ignored. It does not write the device best |
| `/?replay=demo`, `/?replay=edits`, `/?bench=stress&seed=1` | Unchanged lines. Pointer and keys are now ignored. No sign and no panel is drawn |

The scripted body is one command: tick 0, `AddRoute [0,1]` on scenario 0. Station 2 is never served, so its queue overflows and the game ends. The same game can be played with real input: pause in `Menu`, drag station 0 to station 1, resume. The paused edit binds to tick 0 (Q10).

## Line formats

```text
salmong: game ready scenario=<id> seed=<seed> mode=<play|replay>
salmong: game start
salmong: game tick=<t> score=<s> hash=<16 hex>
salmong: game clock paused=<0|1> speed=<1|2> tick=<t>
salmong: game over tick=<t> score=<s> hash=<16 hex> best=<score>,<ticks>
```

`ready` is written at boot and at each restart. `start` is written on the first press, in play mode only. One `tick=` line per multiple of 150. `clock` is written when pause or speed changes, never under a `ReplayFeed`. `best=` is `BestRes` after this run was recorded, or `none`. A game driven by a `ReplayFeed` (`?replay=over`) is never recorded, so its `best=` is the best loaded at boot.

## Shapes on screen

Grid units, y down, grid 64 x 40. A grid point `(x, y)` is pixel `((W - 64 s)/2 + x s, (H - 40 s)/2 + y s)` with `s = min(W/64, H/40)` for a `W x H` canvas, as in M3.1.

| Shape | Where | Colour |
|---|---|---|
| Pause sign: two bars, half size (0.3, 0.9) | centres (60.5, 2) and (61.5, 2) | `#14213D` |
| x2 sign: two triangles pointing right, half size 0.8 | centres (57, 2) and (58.4, 2) | `#14213D` |
| Pending edit: line through the stops, half width 0.07 | under the stations | `#111111` |
| Panel | centre (32, 20), half size (12, 7) | `#14213D` |
| Run row: circle of radius 1.0 at (24, 17), then digits | digit k (0 is the leftmost) centred at (28 + 2.2 k, 17) | white |
| Best row: star of radius 1.2 at (24, 23), then digits | digit k centred at (28 + 2.2 k, 23) | star `#FFD60A`, digits white |

A digit centred at `(cx, cy)` has seven segments. Horizontal ones have half size (0.55, 0.15), vertical ones (0.15, 0.55).

| Segment | a | b | c | d | e | f | g |
|---|---|---|---|---|---|---|---|
| Centre | (cx, cy - 1.4) | (cx + 0.7, cy - 0.7) | (cx + 0.7, cy + 0.7) | (cx, cy + 1.4) | (cx - 0.7, cy + 0.7) | (cx - 0.7, cy - 0.7) | (cx, cy) |

Lit segments: 0 `abcdef`, 1 `bc`, 2 `abdeg`, 3 `abcdg`, 4 `bcfg`, 5 `acdfg`, 6 `acdefg`, 7 `abc`, 8 all, 9 `abcdfg`. A lit segment centre is white; an unlit one is the panel colour. The driver reads each number from the screenshot this way and compares it with the console line. The app does not grade itself.

## Laptop procedure

Reference laptop and command-line route of [m0.3-webgpu-check.md](m0.3-webgpu-check.md). The driver is a CDP script kept outside the repository. No fixed window size is needed: record the canvas size and device-pixel ratio and map with the measured size. Keep the window visible and on one display.

1. On the box write `expect-over.txt` and `expect-idle.txt` with the two `over_expect` commands. Each holds the `tick=` lines, the `game over` prefix, `grid 64 40` and `sample <kind> <x> <y> <r> <g> <b>` lines for the game-over frame. The best row defaults to the run score; `--best <n>` sets it and `--best none` draws the star with no digits (S1 on an empty profile). For P15 use `over_expect idle --best <first score>`. The idle game has no route, so it has no `route` sample.
2. On the laptop build the unit commit with `trunk build --release --offline` and serve `dist/`. Also keep a `dist/` of main d86b407 for the two negative controls.
3. Start a separate Chrome with its own empty `--user-data-dir`, `--force-color-profile=srgb` and the WebGPU flags of M3.1. Send keys with `Input.dispatchKeyEvent` (`code` `Space`, `Digit1`, `Digit2`, `Escape`, `Tab`) and the mouse with `Input.dispatchMouseEvent`. Count draw calls per frame with the M5.2 page hook.
4. Run the rows below in order. Save every screenshot and the console log.
