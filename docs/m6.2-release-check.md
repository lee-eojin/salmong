**Status: PENDING (laptop).** This file holds the sound part of M6.2 (unit `m6-2-audio`): six sound effects, the mute key and its sign, and audio after the first gesture. The art unit (`m6-2-art`) writes its own sections of this file, and the licence and hosted parts add theirs when their units land. The box rows below were run for this unit. No laptop row has been run.

## Sound

Sounds follow `SimEvent` in presentation only. `salmong_game::sound` reads `SimEventMessage`, takes no mutable access to `SimRes` and never calls `Sim::queue` or `Sim::step`, so `state_hash` does not change. `bevy_audio` and `wav` are wasm32-only features, so the native build is silent; every rule below except playback runs and is tested natively.

| `SimEvent` | `Cue` | File | Samples | Sound | Volume | Gap |
|---|---|---|---|---|---|---|
| `Boarded` | `Board` | `board.wav` | 1,102 | triangle 440 Hz | 0.35 | 90 ms |
| `Delivered` | `Deliver` | `deliver.wav` | 2,646 | triangle 660 then 880 Hz | 0.6 | 90 ms |
| `StationSpawned` | `Station` | `station.wav` | 6,615 | triangle 523, 659 then 784 Hz | 0.7 | 0 |
| `OverflowStarted` | `Overflow` | `overflow.wav` | 6,615 | square 196 Hz, two pulses | 0.8 | 0 |
| `CommandRejected` | `Reject` | `reject.wav` | 3,307 | square 147 Hz | 0.5 | 0 |
| `GameOver` | `Over` | `over.wav` | 19,845 | triangle 392, 330, 262 then 196 Hz | 0.9 | 0 |
| `Spawned`, `Alighted` | none | | | | | |

- **Files.** `assets/sounds/`, 22,050 Hz, mono, 16-bit PCM, 80,524 bytes in total, embedded in the wasm with `include_bytes!`. `scripts/make-sounds.mjs <dir>` writes them with integer maths only. `scripts/check-sounds.sh` regenerates them, compares the bytes and fails if the total is over 100,000 bytes.
- **Shape of a note.** A file splits into equal notes. Each note starts at phase 0, rises over 44 samples (2 ms) along `(i / 44)^4`, then falls in a straight line to zero at its last sample. The peak is at most 16,384, half of full scale. The first and last 16 samples of every file stay within 512 of zero. The rise is not a straight line because a straight 2 ms rise reaches 34% of the peak at sample 15, which is over the 512 limit.
- **Throttle.** `pick_cues` writes at most one of each cue per frame, and at most one per gap of real time. Nothing is written while muted or under a `ReplayFeed`, so `?replay=` and `?bench=` pages are silent.
- **Voices.** `play_cues` (wasm only) skips `Board` and `Deliver` while 12 sounds play.

## Mute

- **Key.** `M`, pressed once (no repeat), in `Menu`, `Playing` and `GameOver`. It is ignored while Control, Super or Alt is held, under a `ReplayFeed`, and in `Loading`. A held modifier is forgotten when the window loses focus.
- **Line.** Each press writes `salmong: game mute=<0|1>`.
- **Store.** `localStorage["salmong.mute"]` is `1` while muted and absent otherwise. Natively the file is `$XDG_DATA_HOME/salmong/mute`, or `$HOME/.local/share/salmong/mute`. Only the text `1` boots muted. A failed save keeps the choice for the session and warns once.
- **Silence.** Muting stops every playing sound in the same frame (`hush`).

The mute sign is drawn only while muted. It is three quads in the `Buses` layer mesh, so the draw count does not change. Grid units, y down, grid 64 x 40:

| Slash, half width 0.1 | from (62.1, 2.7) to (63.7, 1.3), on top | `#D00000` |

Sample points: (62.3, 2.2) and (63.1, 2.3) are `#14213D`, (62.9, 2) is `#D00000`, (62.2, 2) and (63.4, 2) are clear. The pause bars end at x 61.8.

## First gesture

Bevy creates the `AudioContext` at app start, and Chrome keeps it suspended until page code calls `resume()` after a gesture. A classic script in `web/index.html`, before Trunk's module script, wraps `window.AudioContext`, keeps every context the page makes, and resumes the suspended ones on `pointerdown`, `mousedown`, `keydown` and `touchend` (capture phase). `window.salmongAudio()` returns `none`, `suspended` or `running`.

`play_cues` plays a cue only when `window.salmongAudio()` is `running`. Otherwise it drops the cue and warns once per page load: `salmong: audio suspended, cue dropped`. On `/` no `SimEvent` exists before the first left press, and that press is the gesture, so normal play loses no sound.
